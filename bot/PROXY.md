# پروکسی اختصاصی RDNET

این قابلیت اختیاری است و نصب‌کنندهٔ اصلی VPN آن را فعال نمی‌کند.

نصب اصلی، فایل‌های منوی پروکسی را همراه بات نصب می‌کند. سپس برای فعال‌کردن
سرویس عمومی، اسکریپت مستقل زیر اجرا می‌شود؛ این تفکیک از بازشدن ناخواستهٔ
پورت جلوگیری می‌کند. نصب روی بات جدید همین نسخه یا نسخهٔ قبلی تأییدشده
پذیرفته می‌شود. نصب تکراری روی پروکسی موجود، پیش از تغییر متوقف می‌شود؛
این اسکریپت ابزار ارتقای نصب موجود نیست.

پورت اشغال‌شده رد می‌شود؛ تنظیمات Xray و WireGuard تغییر نمی‌کنند و فقط
یک قانون به فایروال افزوده می‌شود. در خطای نصب، بات و فایل فایروال از
بک‌آپ برمی‌گردند و فقط قانون پروکسی حذف می‌شود. هنگام نصب، بات یک بار
restart می‌شود. سازگاری همهٔ محیط‌ها تضمین نشده و تست نصب کامل روی سرور
تازه هنوز انجام نشده است.

## پنل بات

در گفت‌وگوی خصوصی مدیر: `/vpnadmin` ← «پروکسی اختصاصی» یا `/proxyadmin`.
فرم: نام فارسی یا انگلیسی، حجم دلخواه (GiB، مجموع ارسال و دریافت)، تعداد IP
هم‌زمان (1 تا 32)، IP/CIDRهای مجاز یا `*`، و تأیید نهایی. یوزرنیم و رمز
تصادفی و URI اختصاصی `https://user:password@host:port` تحویل داده می‌شود.
هر حساب یک سهمیهٔ مشترک دارد، نه سهمیهٔ جدا برای هر IP. رمز فقط هنگام ساخت
یا بازنشانی نمایش داده می‌شود و به شکل PBKDF2 در پایگاه داده نگهداری می‌شود.
فهرست حساب‌ها، مصرف، قطع دسترسی و بازنشانی رمز در همان پنل موجود است.

محدودیت IP هم‌زمان، تعداد دستگاه نیست: دستگاه‌های پشت NAT یک IP محسوب
می‌شوند. هر حساب تا 128 اتصال TCP دارد تا مرورگرها بتوانند هم‌زمان کار کنند.
IP تا بسته‌شدن آخرین اتصال آن حساب اشغال است؛ اتصال بیکار پس از 120 ثانیه
بسته می‌شود. IPv6 ورودی فعلاً فعال نیست. محدودیت IP مانع بازنشر اتصال توسط
کاربر مجاز نمی‌شود.

حجم پیش از ارسال هر قطعه، اتمیک رزرو می‌شود؛ مصرف پس از ری‌استارت حفظ
می‌شود. اگر حجم باقی‌مانده از قطعهٔ بعدی کمتر باشد، اتصال بسته می‌شود و ممکن
است چند کیلوبایت سهمیه باقی بماند. قطع دسترسی یا تغییر رمز، اتصال‌های باز را
حداکثر حدود یک ثانیه بعد می‌بندد. آمار شامل بایت‌های عبوری است، نه سربار TLS
و TCP؛ هنگام شکست ارسال، رزرو حجم ممکن است اندکی بیشتر از تحویل واقعی باشد.

## مسیر و امنیت

کلاینت ← TLS/TCP روی پورت مستقل ← احراز هویت و سهمیه ← پروکسی داخلی
`127.0.0.1:10808` ← مسیر فعلی Xray/WireGuard. مسیر جایگزین مستقیم وجود ندارد.
این قابلیت به‌تنهایی جایگزین TCP برای تونل خارجی WireGuard ایجاد نمی‌کند.

فقط مقصدهای عمومی روی پورت‌های 80 و 443 پذیرفته می‌شوند؛ IPهای خصوصی،
loopback، link-local، آدرس عمومی خود سرور و سایر مقصدهای غیرعمومی رد می‌شوند.
DNS یک بار بررسی و IP عددی به upstream داده می‌شود. درخواست HTTP معمولی و
CONNECT برای HTTPS پشتیبانی می‌شود؛ ارسال chunked HTTP و HTTP upgrade در
ورودی معمولی پشتیبانی نمی‌شوند. نرم‌افزار مصرف‌کننده باید **HTTPS proxy**
را پشتیبانی کند؛ HTTP proxy بدون TLS روی اینترنت باز نمی‌شود.

بات فقط helper ثابت با JSON محدود را اجرا می‌کند. helper امکان اجرای فرمان،
SQL یا مسیر فایل دلخواه ندارد. رمزها وارد audit نمی‌شوند. منو و مشخصات فقط
در گفت‌وگوی خصوصی Owner/Admin ارائه می‌شوند.

## استقرار با تأیید مدیر

قبل از اجرا: کد را بررسی کنید؛ گواهی معتبر دامنه، کلید متناظر، پورت خالی و
اجازهٔ بازکردن پورت عمومی را تأیید کنید. نمونه برای سرور بررسی‌شده:

```bash
sudo bash bot/install-proxy.sh --apply x.dimamotor.com 8443 \
  /root/.acme.sh/x.dimamotor.com_ecc/fullchain.cer \
  /root/.acme.sh/x.dimamotor.com_ecc/x.dimamotor.com.key 87.248.156.48
```

اسکریپت نسخهٔ فعلی بات را با SHA256 بررسی می‌کند، بک‌آپ می‌گیرد، سرویس
مستقل و helper را نصب می‌کند، فقط پورت انتخابی را به فایروال اضافه می‌کند و
بات را ری‌استارت می‌کند. تنظیمات Xray و تونل خروجی تغییر نمی‌کنند.
پس از صدور مجدد گواهی باید فایل‌های TLS را با مالکیت root:rdnet-proxy و مد
640 در `/etc/rdnet-proxy` به‌روزرسانی و سرویس پروکسی را restart کنید.
timer تمدید خودکار نصب/فعال نشده؛ برای فعال‌کردن
همگام‌سازی خودکار گواهی، تأیید جداگانه مدیر لازم است.
نصب‌کنندهٔ اصلی به‌روز‌شده include فایروال پروکسی را حفظ می‌کند. نسخهٔ قدیمی
ممکن است آن را پاک کند. از accounts.db با دسترسی محدود بک‌آپ
بگیرید. در بوت فقط یک نمونه از سرویس پروکسی اجرا کنید؛ شمارش IP در حافظهٔ
همین نمونه است.

## بازگشت

`systemctl disable --now rdnet-proxy` را اجرا کنید؛ قانون دارای comment
`rdnet-proxy` را با handle از chain input حذف کنید، خط include را از
`/etc/nftables.conf` بردارید، فایل بات را از بک‌آپ چاپ‌شدهٔ نصب برگردانید و
بات را restart کنید. حساب‌ها و آمار را برای بازیابی نگه دارید. قوانین دیگر
فایروال را flush نکنید.

## اعتبارسنجی توسعه

آزمون‌های هسته (نیازمند cryptography فقط برای تولید گواهی تست) و فرم بات
(نیازمند requirements.txt بات) بدون تماس با تلگرام اجرا می‌شوند:

```bash
python -m unittest discover -s bot -p 'test_proxy*.py' -v
bash -n bot/install-proxy.sh
```

16 آزمون هسته شامل TLS، HTTP/CONNECT، سهمیهٔ مشترک اتمیک، سقف IP، اکسس‌لیست،
قطع اتصال، بازنشانی رمز و نبود fallback مستقیم؛ 4 آزمون فرم شامل دسترسی
خصوصی مدیر، ورودی نامعتبر، لغو و جلوگیری از ساخت تکراری اجرا شده‌اند.
نصب روی سرور و آزمون end-to-end از اینترنت، پس از تأیید استقرار انجام می‌شود.
